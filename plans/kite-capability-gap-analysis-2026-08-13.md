# Kite capability gap analysis

Date: 2026-08-13
Code baseline: `363ff379dcf1ced97ba8b77753aacdaa60f37dfe` plus the uncommitted working-tree changes present during this audit
Benchmark: [`plans/common-downloader-capabilities-research.md`](common-downloader-capabilities-research.md), refreshed from official product pages, official help/release material, official repositories, and the aria2 manual on 2026-08-13

## Executive conclusion

Kite is no longer short on raw protocol breadth. The repository contains HTTP/FTP, BitTorrent, Metalink, queue control, retry, schedules, Keychain credentials, proxy settings, browser packages, RSS, remote control, post-processing, and updates. This round establishes a real pre-commit staging layer for direct links and local Torrent/Metalink files. The remaining product gap is no longer “there is no preview”; it is making that staging layer fully recoverable, truthful about effective network policy, and consistent under packaged-app interaction.

The highest-leverage work is therefore:

1. finish the New Download sheet's recovery and policy feedback: row-level retry/removal, explicit commit outcomes, dirty-draft protection, redirect/range detail, and effective proxy/auth disclosure;
2. finish Settings validation and health checks now that automatic persistence, restart-required state, and credential-deletion confirmation exist;
3. complete the still-unverified Torrent, destructive-action, Inspector, and alternate-entry scenarios without generalizing the successful package and focused GUI checks into blanket interaction coverage.

This document deliberately does **not** interpret a stored property, service type, engine option, or `Docs/FEATURE_PARITY.md` row as proof of a user-visible feature. For example, `noDirectFallback` remains a model field (`AppSettings.swift:114-120`), but its unconnected Settings toggle was removed and the engine argument builder does not consume it; the media model contains audio/subtitle fields, but the current Settings UI and download request use only preferred height. Those are not complete UI capabilities.

## Status and evidence rules

- **[已实现且可见]**: a user entry point and its action path are both present in the live files.
- **[已实现但发现性/交互不足]**: the action path exists, but setup, feedback, status, or recovery is too hidden or manual for the mature-product baseline.
- **[部分/范围限制]**: a narrower behavior exists and its omitted boundary materially matters.
- **[未实现]**: no user-facing path and no connected runtime path were found in the audited files. An unused model field does not change this status.
- **[外部门槛]**: completion requires signing identity, store account/review, hosted service, or another credential/state that should not live in the repository.

Priority means:

- **P0**: close and verify the requested core interaction in this iteration, or remove a misleading control/claim.
- **P1**: next release; a mature general-downloader expectation with a tractable local implementation.
- **P2**: differentiator, ecosystem expansion, or externally gated release work.

The following code is present in the final working tree as **本轮实现**. The final automated/build/package gates passed; only the explicitly listed GUI scenarios below were exercised, so code/build evidence is not promoted to blanket interaction coverage:

- HTTP/HTTPS preview with a four-request concurrency cap, task-ID cancellation, request-context refresh, selectable URL rows, and parsed-only labels for non-HTTP links;
- asynchronous local `.torrent`/`.metalink`/`.meta4` preview, file selection, selected-size summary, and 1-based `select-file` submission;
- destination free-capacity/conflict-policy summary and unified menu, open-file, deep-link, clipboard, and drag/drop staging routes;
- review hardening for header-only HTTP probes, overflow-safe size totals, latest-wins container imports, and explicit drag/drop rejection;
- toolbar Settings discovery, debounced automatic saving, saved-versus-restart-required state, credential-deletion confirmation, and removal of the misleading no-direct-fallback control;
- cross-section selection clearing, destructive-action confirmations, Inspector reset/empty-selection protection, Dashboard active-list search/empty-state polish, and key Simplified Chinese strings.

### Validation state for this working tree

- **Final-tree automated evidence:** `swift test` completed with **45 tests / 15 suites passed**. This covers preview parsing/network-service behavior (`DownloadPreviewServiceTests.swift:26-235`), including checked-size overflow/negative handling, guarded container parsing (`ContainerPreviewServiceTests.swift:5-191`), `select-file` ordering/empty omission (`AddTaskOptionsTests.swift:4-20`), settings restart snapshots (`SettingsStoreTests.swift:4-40`), and the pre-existing service/model tests; it is not a SwiftUI interaction test.
- **Final-tree build/package evidence:** `./script/build_and_run.sh --verify` and `--package` both passed against the final source. Strict code-signature validation, packaged `Info.plist`/Metalink document registration, `plutil`, `bash -n`, and `git diff --check` also passed. These gates establish build/package integrity, not unlisted GUI behavior or a signed/notarized public release.
- **Focused runtime evidence:** Computer Use verified the main window; all seven Settings tabs; automatic save and Restart Required state (with the changed setting restored afterwards); `⌘N`; Magnet parsing plus duplicate/invalid accounting; an HTTP HEAD preview showing `README.md`, MIME, effective host, HTTP 200, and 8 KB; and deselecting the only URL row disabling Add. No download was submitted during these checks.
- **Focused Metalink evidence:** importing a temporary `.meta4` displayed `Metalink · 2 files · 3 KB`, two selectable files, `2 of 2 files selected`, and `Selected size: 3 KB`. Deselecting `file-one.bin` changed accessibility state to `1 of 2`, changed the selected size to 2 KB, and kept Add enabled; Cancel then closed the flow without submitting. The temporary fixture was deleted.
- **Still pending:** the focused pass does not establish every Open/deep-link/drag/drop/clipboard route, the new mixed/multi-container/unsupported-drop rejection UI, rapid successive container imports, Torrent preview, malformed/large container, actual Torrent/Metalink submission or retry, Dashboard filtering while active tasks exist, overflow/unknown-size presentation, destructive confirmation, Inspector, localization layout, or full accessibility scenario.
